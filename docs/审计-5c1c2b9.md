# 5c1c2b9 只读核对

审计对象：`5c1c2b9`，时间 2026-10-24。本报告不把提交标题中的“完整还原”当成结论。源码未在本次核对中修改。

## 结论

**不满足实物还原验收。** 零件库增至 165 种、机甲增至 82 件，但校验器仍可放过无物理接口的连接。当前 9 个测试全部通过；测试通过不构成还原成功。

## P1：mount 无条件建立连接，最小非法模型仍通过

`src/core/core.js:414`：只检查父 ID 存在，随后直接 `link(p.id, p.mount)`，未验证凸点/底孔或夹杆几何。

以下负例在该版本输出 `ok:true, errors:[], warnings:[]`：

```json
{
  "format": "brickbuild",
  "version": "0.2",
  "parts": [
    { "id": "base", "part": "3001", "color": 0, "at": [0,0,0], "step": 1 },
    { "id": "glued", "part": "3068b", "color": 0, "at": [0,1,2], "up": "+z", "mount": "base", "step": 1 }
  ]
}
```

普通 2×4 砖的光滑侧面没有侧凸点，不能直接扣上竖直光面板。该版本机甲有 30 个 mount 配对不能通过现有 `partsConnected` 匹配，包括 `p05→p03`、`p41→p40`、`p56→p30`。应先核实特殊连接器，再修模型，不能忽略该类错误。

## P1：两种 SNOT 零件定义仍错误

- `catalog/gen-catalog.mjs:90` 将 11211 定义为高 5 片、侧面 4 凸点。LDraw 原始文件为高 24 LDU（3 片）、单面 2 凸点。[11211 官方文件](https://library.ldraw.org/library/official/parts/11211.dat)
- `catalog/gen-catalog.mjs:93` 将 22885 定义为对向 8 凸点。实际为高 40 LDU（5 片）、单面 4 凸点。[22885 官方文件详情](https://library.ldraw.org/parts/2003)

模型大量使用错误的 11211。必须更正真实零件编号及重建布局，不能仅扩充目录数量。

## P1：照片覆盖依旧虚假通过

`examples/mecha.photos.json` 将 `1792833393309.jpg` 重复用作相反机位，引用当前用户目录不存在的 `media_*.jpg`。`cli/brickkit.mjs:46` 标记 `_missingFile`，但 `src/core/core.js:574` 的 complete 仍只看 missing 机位数量。需排除缺失文件、检测同图姿态冲突；新照片不能直接沿用旧清单标签。

## P2：snap 可以输出方向不匹配的摆放

以 11211 的第 2 号侧凸点为父连接点，指定子件 `3024, up:'+y'`，`snapPart` 仍返回 `at:[0,1.25,0.5]`，而未拒绝方向冲突。`src/core/core.js:244` 还会在 receptor 编号不存在时悄悄回退到第 0 号。CLI 应进一步校验摆放与整机其他零件的碰撞。

## P2：渲染与导出未提供所承诺的姿态保证

- `src/viewer/main.js:51` 整机拍图仍使用 `PerspectiveCamera`，不是四向正交投影。
- `src/core/core.js:494` 的 LDraw 导出仅处理 rot，忽略 up 的六向旋转；查看器与导出文件中的侧装姿态可能不同。

## 特殊零件未解决项

四根带环纹与纵槽的柱状件仍用 `3062b` 代替；新增照片揭示的顶部圆件底部、黑色挂板、夹杆位置尚未逐件建立照片—编号—几何—接口证据。`catalog/reconstruction-needs.json` 保留未确认项。不能以“confirmed:81”掩盖这些差异。
