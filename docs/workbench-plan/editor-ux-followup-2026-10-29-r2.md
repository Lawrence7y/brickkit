## 当前证据和结论边界

用户反馈：滚动时模型虽持续可见但逐帧跳动；添加过程中出现 PNG 被当 JSON 的错误；零件库预览旋转卡顿；移动零件难理解，要求鼠标直接拖动；进入图纸后不能正常返回，顶部添加区模型消失。

2026-10-29 审阅源码发现（不是本轮浏览器性能复测）：

- viewer/main.js 的 stage drop 对任意文件调用 f.text()→openFileText→importText；没有先分辨图片/JSON。用户截图明确显示 PNG 文件头进入 JSON 解析。尚不能判定用户是拖图片还是其他入口误传，必须记录事件路径并复现。
- scroll-transition.js 的 schedule(p) 在已有 rAF 时丢弃新 p，回调采用第一次事件的旧值；这是代码缺陷。set 每次读布局并写 left/top/width/height；onResize 和 ResizeObserver 又调用 renderer.setSize，是滚动性能候选瓶颈，需 profiler 确认其耗时比例。
- main.js 的详情预览 pointermove 直接 place()+render()，同时详情面板也有 pointermove→adapter.orbitBy 路径，需检查同次手势是否双重处理。不要未取证就声称唯一根因。
- setDisplayMode('book') 保留 display.mode='book'；返回搭建按钮没有设回 3d；主渲染循环在 book 模式直接 return。因此存在返回搭建后仍不更新主场景的明确状态缺口。

## 1. 滚动必须逐显示帧连续

从搭建到展示继续使用同一个模型、同一个实例状态。滚轮事件只更新最新 targetProgress；统一 rAF 消费最新目标，禁止闭包滞留旧进度。通过短时收敛跟随目标，反向立即响应，不排队补播旧滚动；停止后约 200ms 内收敛，终点和返回状态可靠到达。reduced-motion 允许直接跟随。

优先固定 WebGL 绘图缓冲尺寸，移动/等比缩放由外层 transform 承担；合理限制 DPR/过渡分辨率，稳定后再提升清晰度。若选另一方案必须用性能证据证明，不要每一个 scroll 像素同步重分配 GPU 缓冲。起终点矩形预计算，resize 才失效，逐帧读写分阶段。不得靠降低整个模型渲染频率制造“节能”的跳动。

验收：真实鼠标滚轮、慢滚、快速反向、触控板等价连续输入；视频和连续 rAF 时间/进度/模型屏幕位置，保留最慢区段。参考 60Hz 实机 p95 帧间隔≤25ms、无>100ms可见停顿；注明设备/GPU/软件渲染后端，未达标如实报告。仍检查全过程可见、无形变、姿态和撤销历史不变。不能用每5%一张截图证明丝滑。

## 2. 文件和内部拖拽必须分流

模型打开入口清楚命名“打开模型”，支持实际已有的模型/草稿格式。扩展名、MIME 与内容头联合分类；JSON 解析前拒绝 PNG/JPEG 等二进制图片，用户提示“这是图片，当前入口用于打开模型（JSON）”，不能显示乱码或原始异常。若当前没有照片重建入口，只说明用途，不能伪造导入成功或自作主张启动识别。

内部待选零件拖拽用自己的 DataTransfer 类型和实例信息；不得落入外部文件导入分支。拖零件、拖图片、拖合法模型、损坏 JSON、多文件、空 type 等分别测试；只允许明确支持的输入改变文档。按钮打开和文件拖入统一执行未保存修改保护；拒绝输入对模型、待选区、pose、revision、history、dirty 均零副作用。

## 3. 零件详情旋转跟手

详情弹窗拖动使用单一路由和同一个持续存在的预览场景；pointermove 只累计角度/目标，rAF 至多渲染一次。禁止每次移动重建几何/材质、生成缩略图或 toDataURL；缓存几何和资源，关闭弹窗清理事件/渲染器，隐藏时停止自动旋转。库卡片默认静态，只有当前详情按需动画。检查是否主场景、缩略图队列、图纸生成在争用主线程。

验收简单板和目录中实际最复杂零件：左右/上下自由旋转、快速反向、自动旋转、拖动暂停自动旋转、关闭再开、连续切换20次。记录实际帧时间和长任务，不把“角度值变化”算流畅。性能目标及硬件说明同第1项。

## 4. 默认就是鼠标抓住零件拖动

搭建模式：左键按住零件超过4px即开始移动预览，零件持续跟随指针；短按仅选中。左键拖空白旋转相机，右键拖空白平移相机。拖零件必须在捕获阶段暂停相机控制，松手/取消/失焦都恢复，不要求快捷键或先找“移动”按钮。

默认在零件起始高度平面内射线投影移动，自动吸附实际合法连接；显示幽灵件、落点、合法/非法颜色及简短原因。选中后出现中文“上移 / 下移 / 旋转90° / 取消”控件，供高度和朝向调整，鼠标就能完成，不强迫输入XYZ。自动吸附候选不得导致远距离跳跃。

松手合法即提交一次事务；非法回到起始位置并解释，禁止留下穿模或悬空的正式模型。Esc、pointercancel、窗口失焦取消回原状态，历史不增加。拖动已有连接件只改变预览；松手需明确展示将解除的连接，如会影响其他依赖，提供“只移动这件 / 移动相连组件 / 取消”选择，不能暗中把全模型带走或隐式断开依赖。组件选择范围必须在提交前高亮。

待选区直接拖入模型：移出卡片后进入同一放置预览流程，合法松手完成添加；点击取件再点击放置保留为替代方式。添加数量只在成功提交后扣减，失败不丢件。

试玩模式左键拖可动件按已有关节自由度运行，固定件不被拆走；显示轴/弧/箭头及就地说明。搭建移动与试玩运动明确区分但不增加复杂模式。所有最终请求仍走已有真实连接、碰撞、运动准入，严禁放宽规则凑体验。

验收只用鼠标完成：选件→改色→拖入→直接拖动改位置→上移/旋转→非法回退→撤销/重做→试玩开门；含拖动后相机不跟着转、多零件依赖确认、触屏取消。

## 5. 图纸永远有出口，返回恢复全部编辑状态

统一三个显式状态：搭建、3D展示、图纸。图纸页固定可见“返回3D预览”和“返回搭建”；长图纸滚到底、图纸生成中/失败后都可点。返回搭建必须先退出 book 模式、取消/失效旧图纸任务、恢复主渲染与视口，再重置过渡/滚动。滚动返回途中不得再次被 scroll 监听切回图纸/展示。

返回顶部恢复待选条、零件库按钮、所有待选缩略图、颜色/数量和编辑工具的可见性/命中；模型、当前关节姿态、选择、历史与未保存状态保留，不重载示例。缩略图或主画布隐藏期间取到0尺寸时，不得永久停止渲染；显示后触发正确尺寸与绘制。

验收闭环连续10轮：编辑添加一件并改色→试玩改变姿态→下滚→图纸→滚到底→返回搭建→继续拖动/添加→撤销→再进入3D。另测图纸生成中返回、返回后旧异步任务完成、resize及刷新恢复。检查完整页面状态、实际画面和按钮命中，不能只断言 data-view。
