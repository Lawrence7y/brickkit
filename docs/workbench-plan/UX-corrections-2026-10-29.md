# 工作台体验修订：五项用户反馈（2026-10-29）

本文补充PRD.md；与旧交互/验收冲突时以本次用户反馈及本修订为准。不能以已有套件通过否定用户反馈。本轮审阅冻结构建为221a228280ce…，证据在主目录out/workbench-ux-review-2026-10-29/。本文件是实施规格，不声明问题已修。

## 一、编辑到展示：滚动全程模型都在屏幕中

### 已复现

1440×900下：scrollY=494时模型已部分越过屏幕顶部；741时模型几乎完全离开；988时模型投影y=-638..-245，完全不可见；1481附近才重新出现，1646到展示终点。进入展示成功只证明终点可达，不证明连续过渡成立。

原因：进度等轨道顶越过视口才开始，而首屏先正常滚走；过渡矩形又取实时stage.getBoundingClientRect，其起点早已是负y。不能拿随页面滚走的源矩形当作固定舞台的动画起点。

### 必须改成

- 同一个场景/同一模型实例贯穿编辑、过渡、展示；模型不消失、不替换成图片、不在末尾重新出现。
- 用户从首屏开始下滚时就进入连续过渡；使用固定/粘性舞台承载。布局空间用占位维持，不让承载canvas先离开屏幕再接管。
- 开始矩形在过渡启动时冻结；终点在稳定的视口坐标系计算。反向滚动按同一函数原路恢复；resize重新计算但保持进度，不瞬移。
- 整个模型按一个比例缩放并平移，朝向、颜色、已显示关节姿态和实例身份保持；不修改零件物理坐标。工具淡出/展示控件淡入不能遮住或带走模型。
- 起点为工作台可见构图，终点为展示左栏安全构图；中间各点均在顶栏以下、浏览器视口以内的安全区。用完整几何投影判断，不只看canvas矩形或零件原点。
- 使用当前显示姿态取景，取下屋顶也应包含在安全构图内；普通滚动不应造成相机方向重置。
- 保留旧版已修的终点可达性、上滚返回、模式稳定和滚轮不被相机吞掉。

### 验收

真实滚轮采样整个行程0/5/10…100%，逐点暂停，检查模型完整可见；含首次下滚、缓滚、快速滚、反向、窗口缩放、五尺寸、reduced-motion和关节已打开/屋顶已取下两态。必须有全程视频/帧序列和逐点几何投影指标，不能只给起终点截图。

## 二、默认操作：看得懂、点得到、不必学快捷键

### 页面默认呈现

- 左工具条显示中文名称，默认仅「选择」「涂色」，其余进入选中零件后的就地工具；V/G/R等仅辅助提示。
- 模型区空态只显示「从零件库挑选零件，再从待选区取出搭建」。非空待选项就地提示「点击取出，移到模型上放置」。不以长说明书或强制教学替代易用交互。
- 默认不显示实例ID、全部固定端清单、接口编号、世界坐标；进入属性「高级」才展开。简版使用「已连接到…」「未连接」「可转动」等中文。
- 顶部「搭建 / 试玩」继续保留。切换后给一句对应提示；试玩时直接拖活动件，搭建时点击选择，不再要求用户主动选择内部工具状态。

### 主流程

1. 零件库点击卡片打开可旋转详情，详情有明确主按钮「加入待选」；卡片另有同名快捷添加按钮，不影响点击模型区域开详情。
2. 点击待选卡取件，模型显示半透明预览和合法吸附点；移到目标位置后单击落位。Esc或鼠标右键取消，旁边同时有中文「取消」按钮，不强迫记按键。
3. 支持拖拽作为另一条自然路径：合法位置松手即落位；非法位置不提交，保留预览并给简短原因。此条覆盖旧PRD“拖拽释放后必须再点确认”的规定。点击取件与拖拽共用准入/事务，不能双重提交。
4. 预览旁显示「旋转」「换个扣合位置」「取消」；仅存在多个合法候选时出现切换入口，内部接口编号留高级面板。位置合法才显示可落位，不能以颜色掩盖接口缺口。
5. 点击已装零件出现就地操作「换色 / 移动 / 复制 / 拆下」。简单改色不弹确认；会断开其他件时才简明解释影响并提供选择。
6. 试玩点击活动件显示方向弧/箭头、允许方向和限位；被拦时指出原因及对象。门0°不能向负角打开时，界面给方向提示，不让用户猜。

### 验收

在无键盘、无内部API调用、无事先阅读说明的条件下，用鼠标完成挑选→待选改色→放置→旋转/重扣→换色→撤销→试玩开门→进入展示→返回。手机使用触摸完成相同主线。不得用增加更多隐藏模式和快捷键来回应学习成本问题。

## 三、零件库：修真正重叠，并保证能看清

### 已复现与根因

1440×900下前3张卡片都在x192/y262；1280与390宽下同样同坐标重叠。library.css把canvas/card设为绝对定位；virtual-grid.js却按CSS Grid写gridTemplateColumns并只插入顺序，没有给每张卡left/top。因此所有卡压在同一位置。

这不是仅缩小列数可解决的密度问题。统一采用一种布局：本轮推荐可视行窗口内部CSS Grid＋上/下占位维持总高，卡片position:relative；如果选择绝对虚拟网格，必须明确每卡坐标与宽高，不能两种机制混用。

### 显示规格

- 默认卡宽至少160px、高208px、间距16px；预览区域高128px，名称最多两行，编号/尺寸独立一行。所有盒子使用border-box，图像不能撑破卡片。
- 标准灰模、统一3/4观察方向、独立按零件完整包围盒取景，占预览区域约70%～80%；长板不截断，小零件不只剩一粒点。背景浅灰、边缘清楚。
- 预览图区域点击开详情，底部「加入待选」按钮独立可点。能力标记不盖住零件主体。
- 桌面依据可用宽度算列数，手机分类变横向、网格两列；窄于两卡最小宽时才一列，不强行压缩卡片文字。
- 搜索、换分类、改变窗口宽度、滚动复用时都重新测量可用内容宽度；保留当前浏览位置和选中状态。
- 完整保留虚拟化，不能为了避免重叠一次创建4605个canvas/完整3D场景。

### 验收

五尺寸中检查所有可见卡片矩形两两不相交、行列间隔、预览尺寸和文本边界；随机点击至少10张不同位置卡片，打开的编号必须与可见卡一致。搜索/分类/列表滚动/resize后重复检查。不再以“卡片少于300张”代表网格正确。

## 四、零件库打开：先响应，再补内容

用户反馈为打开时卡顿。审阅方在无头Chrome/SwiftShader下测得一次冷打开：openLibrary同步调用约497ms，后续捕获约3921ms长任务，双rAF约4196ms；不能把软件渲染耗时直接当作用户GPU表现，但主线程阻塞已有证据。见latency-animation.json。具体函数归因仍需性能剖析。分别测首次打开、再次打开、换分类/搜索，记录click→可见弹窗外壳、首批卡片、首批实际缩略图及long task。

- 点击立即给按下反馈，先绘制弹窗外壳和搜索区，再分批填入索引/可见卡片。不能同步算完整接口统计再显示弹窗。
- 静态分类/名称索引可预处理或后台准备；重的接口统计按需或缓存，不在每次open/filter里重扫全部零件。
- 首先生成可见卡片缩略图，超视口任务可取消/降优先级。只在空闲预算内生成，重建WebGL上下文和同步toDataURL均需量测；图像编码/缓存选择按证据优化。
- 冷启动显示准确骨架和「正在加载零件」，几何缺失明确说明，不长期用通用占位假装成功。
- 性能目标（记录真实设备、浏览器、渲染后端）：弹窗外壳150ms内出现，重复打开100ms内；可见首批卡片500ms内、实际缩略图尽量1s内完成。头部软件渲染结果单列，不能冒称用户硬件性能。未达目标须报告瓶颈/实测，不虚报。
- 关闭、换分类、快速重复打开能取消陈旧任务；不把旧搜索缩略图写到新卡上。

## 五、展示区开合：必须有中间姿态，且可反向

审阅方已复现门点击打开时cur/target从0/0在点击返回前变成95/95，后续10个真实rAF采样全部停在95，没有中间姿态，见latency-animation.json。不是仅凭用户主观感受推断；需修复状态/渲染衔接而非只延长CSS时间。

- 点击「打开 / 关上」「取下 / 装回」触发一个连续的运动过程，不直接跳到终态。转动默认约450ms，拆装约600ms，轻缓起止；同一组件所有零件按相同关节进度联动。
- 运动途中反向点击，从当前已显示姿态平滑反向，不先跳到端点、不排队补播。其他关节已保存状态保持。
- 拖动滑块/活动件跟手，不强制播放完整定时动画；释放时提交与显示衔接连续。reduced-motion可即时到达，但须明确这是系统设置，不能把普通模式也做成跳变。
- 所有路径仍走admitJointRequest；预检整段路径并保留运行约束，不为动画放宽碰撞。遇碰撞在允许姿态停住，非法姿态不落盘。
- 事务提交若重建场景，保存并恢复渲染起始姿态与动画目标，不让load把cur和target同时设成终值。该处是待核查路径，不先认定唯一根因。
- 动画期间只提交一次用户命令，不每帧写历史/自动保存；撤销能恢复上次状态。相机取景与关节运动协调，不能每帧重启fit或让模型飞出视野。

### 验收

普通模式点击门、屋顶和独立可动样本，采集中间多个真实矩阵，确认至少存在不同于起终态的姿态；中途反向、连续快速点击、取消、撤销、滚动切换页面、刷新后状态正确。检查完整组件和相机安全区，不只检查pose数字变了。
