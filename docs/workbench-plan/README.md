# 两会话任务分工与集成规则

日期：2026-10-27。目的：编辑工作台与灯笼修复并行，保留当前目录治理修改和历史证据。飞机修复暂缓。

## 发给两个主会话的文件

- 新编辑器会话：先发 editor-session-prompt.md，要求完整读取 PRD.md。
- 原灯笼会话：发 lantern-session-prompt.md，继续当前 v3/v4 证据链，不重新开一套猜测。
- 两个主会话均获授权使用子代理；先定义所有权再并行，不互相派发到另一个用户会话。

## 写入域

| 域 | 所有者 | 另一方规则 |
|---|---|---|
| src/editor及viewer集成、UI测试 | 编辑器主会话（独立工作树） | 灯笼会话只读 |
| 新版灯笼builder、模型、observations、专属验收文件 | 灯笼主会话（当前checkout） | 编辑器只读加载 |
| src/core、catalog、schema通用格式、CLI通用逻辑、旧缺陷表 | 当前已有修改先冻结，原核心修改者负责 | 两会话都不得擅改，登记具体核心请求 |
| build.mjs、dist、共享测试 | 编辑器主会话仅在其工作树集成 | 灯笼不跑共享build，使用专属out目录导出 |
| 本目录PRD与两个提示词 | 本次交付基线 | 后续各会话单独写进度/请求，避免同时改本文件 |

本轮发现现有dirty核心修改与新出现的灯笼v3/v4，均不是空白基线。新工作树必须记录采用哪些未提交文件及哈希；不能只checkout HEAD就宣称继承当前修复。不得把其他会话未完成修改打包成自己的已验证成果。

## 并行安排

- 编辑器主：定义契约、状态、渲染集成；两个子代理分别负责零件库/待选和装配UI，完成后安排只读独立QA。
- 灯笼主：接续当前生成器与模型；一个照片审计代理、一个连接审计代理只读核对，主会话串行落地模型变更。
- 若运行环境最多允许主+3槽，严格受平台限制；不得无上限嵌套。代理少时按同一所有权顺序执行。
- 两个工作树各自使用独立输出目录；不同时写dist、共享golden、生成目录或公共报告。

## 集成交接格式

每次交接注明：HEAD/dirty基线、改动文件、输入模型与目录SHA256、支持能力、未支持能力、运行命令、证据路径、已知问题。模型可以作为快照只读传给编辑器，不要求灯笼全部完成才开发页面。

核心请求最小字段：场景、请求者、现有行为、预期行为、输入/输出示例、影响文件、负例、负责人。核心修改必须只有一个写入者，完成后两个会话都固定到同一修订重新验证；不是遇到请求就停止所有独立工作。

## 完成口径

代码实现、自动测试、真实浏览器操作、照片对照、实物复拼是不同状态。测试数字按通过/跳过/失败分列。灯笼以独立证据确认连接与形状；页面以真实操作和数据不丢失确认可用。禁止把两边任一方完成等同于整个项目已完成。

本文只分配任务与交接规则，不表示已经创建两个用户会话或启动外部Harness。提示词由用户分别发给目标会话。
