## 已确认的根因

1. `mount` 原来无条件建立连接边。普通砖的光滑侧面也能“粘住”竖装平板，悬空件只需填一个存在的父 ID 就可通过。
2. 零件编号错误：`11211` 实为高 3 片、单面两凸点；`22885` 才是高 5 片、单面四凸点，且没有虚构的背面四凸点。
3. 旧清单把 `1792833393309.jpg` 同时标成 90° 和 270°，并引用不存在的 `media_*.jpg`。文件缺失过去只产生警告，仍可能宣布照片齐全。
4. 把带环纹、纵槽的柱状特殊件直接替换成 `3062b` 圆砖并捏造托板连接，外观和接口均失真。特殊件编号仍须确认，不能把检索候选当成识别结果。
5. 翼片和双足的夹杆关节未准确建模。两片前翼共享一个虚构的全局转轴，不能表达各自的实际铰接。
6. 旧 CLI 渲染使用透视相机，尽管文档称其为正交对照；旧 LDraw 导出还忽略了 `up` 方向转换。

## 推进次序

1. 修正校验器的虚假通过路径，建立负向回归和旧样本失败报告。
2. 核实特殊零件：四根柱状件及承接件、双足挂板、翼根夹杆、顶部圆件底部、内部薄板填充。每种记录来源、尺寸、局部坐标、可用接口与几何实现状态。
3. 按核心、双足、四面装甲、四个独立翼根、顶部组件重建；逐模块校验，不能继续挪动旧错误件凑外形。
4. 四向与拆解对照，直到连接及外观均成立，再生成最终交付与用户验收。

## 当前实现边界

本轮曾实现任意挂载校验、收紧连接容差、照片冲突/缺失拦截、两种 SNOT 砖修正、正交渲染及六向 LDraw 姿态，并运行 17 个测试全部通过。但是后续外部提交 `5c1c2b9` 覆盖了这些源码、测试和临时审阅产物；**这些修复并未保留在当前工作树中，17 测试通过也不适用于当前版本**。

当前 `5c1c2b9` 的原有 9 个测试通过，82 件机甲仍由旧校验器判为零错误、零警告。独立只读检查发现 30 条 mount 声明没有匹配的现有连接点；最小负例“普通砖光滑侧面挂竖板”仍被接受。这表示无法按现有定义证实这些连接，不代表已经准确识别了所有实物接口。具体见 `docs/审计-5c1c2b9.md`。

复杂零件目前大量使用参数化近似外形，圆件/斜件的 AABB 不能当成精确实体；夹杆、球头、销轴与机关运动碰撞仍未完整核实。**新模型尚未还原，当前不能签收。**
