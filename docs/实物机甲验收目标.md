## 已确认的根因

1. `mount` 原来无条件建立连接边。普通砖的光滑侧面也能“粘住”竖装平板，悬空件只需填一个存在的父 ID 就可通过。
2. 零件编号错误：`11211` 实为高 3 片、单面两凸点；`22885` 才是高 5 片、单面四凸点，且没有虚构的背面四凸点。
3. 旧清单把 `1792833393309.jpg` 同时标成 90° 和 270°，并引用不存在的 `media_*.jpg`。文件缺失过去只产生警告，仍可能宣布照片齐全。
4. 把带环纹、纵槽的柱状特殊件直接替换成 `3062b` 圆砖并捏造托板连接，外观和接口均失真。特殊件编号仍须确认，不能把检索候选当成识别结果。
5. 翼片和双足的夹杆关节未准确建模。两片前翼共享一个虚构的全局转轴，不能表达各自的实际铰接。

   **2026-10-27 复测（两次，结论递进）**

   第一次复测（当时的目录口径）：转轴位置看似正确——`pivot` 与 `kind:'barplate'` 合成的把柄重合到 0.02 格。

   第二次复测（修复目录合并之后，这才是真相）：**那个「正确」是假的**。合并规则 `{...ext, ...curated}` 是条目级整体替换，精选目录定义过 `48336`/`63868` 后，官方 `.dat` 实测出的把柄/夹口坐标被整条丢弃，接口退回按 `kind` 合成的近似位置。机甲的翼关节正是照那个近似位置写的 `at`。所以「能连上」连的是猜出来的把柄。

   实测依据（LDraw 官方几何）：`48336` 的 handle 圆柱在 `z=-20 LDU = 1.0 格`，杆半径 0.25 格，杆内缘距零件中心 0.75 格 > 半宽 0.5 格——真的悬在边缘外；而合成公式 `hz + 0.22 = 0.72` 会让杆内缘落进砖体内（0.47 < 0.5）。**合成位置本身物理上就不成立。**

   修复合并后按正确库反解，翼夹板应放在 `(-0.35, -0.25, 0.1)` 的偏移处，原坐标扣合判定转 `false`。当前校验器如实报告 6 处 `mount-disconnected`、4 个翼夹板连带 4 片翼板 `floating`、两个 `mech-axis`。此外另有两项与坐标无关的真实缺陷：**行程碰撞**（前翼外摆 10° 即插进 `p76/p48`，后翼 −25°～−35° 撞 `p77/p48`）与**虚假刚体**（前后翼各由两个互不相连的夹板刚体冒充一个关节）。
6. 旧 CLI 渲染使用透视相机，尽管文档称其为正交对照；旧 LDraw 导出还忽略了 `up` 方向转换。
7. **接口数据存在两套来源，且合并时整条丢弃实测值**（2026-10-27 修复）。`catalog/parts-ldraw.json` 由官方 `.dat` 逐图元提取把柄/夹口/销孔坐标；`catalog/parts.json` 是人手核对的身份定义。合并用条目级替换，精选件一律丢掉实测接口。同一份代码被复制在 CLI／查看器／tools／测试共 10 处。此外：
   - `kind:'barplate'` 的合成路径不检查已有实测 `bars`，两套接口**相加**（`48336` 变成 4 根把柄，多出的两根是猜的位置）；
   - `holes` 同名异义：精选目录写数量（数字），扩展目录写坐标（数组），互相覆盖；
   - 生成器遇到 LDraw 的 `~Moved to` 重定向件直接跳过（约占库内 3.8%），`60470` 就是这么「缺」的——件号真实、几何也在，只是搬到了 `60470a`。
8. **校验器只核对尺寸，从不核对接口位置**。`catalog-verify` 比对 `size`/`h` 与官方包围盒，但接口坐标错位不影响任何检查项；`validate` 的机关段也只查字段存在性。

## 2026-10-27 已完成的底层修复（可复现、可回归）

> 结论边界：**找到一个并修复了一个重要的数据合并缺陷，新增检查成功揭露了旧模型的问题。**
> 这不等于「复原偏差的根因已全部解决」，也不等于接口已全部准确、机甲已复原。

- **目录合并收敛为唯一实现**：`mergeCatalogParts()` 取代散落在 10+ 处的 `{...ext, ...curated}`。合并按字段进行，精选目录未显式给出的实测连接器数组（`bars`/`clips`/`holes`/`axleHoles`/`sideStuds`）从扩展目录继承；推断字段（`boxes` 等）不继承。
  - 已统一的入口：`cli/brickkit.mjs`、`src/viewer/geom.js`、`tools/lib/snap-gt.mjs`、`tools/geom-align.mjs`、`tools/box-coverage.mjs`，以及 6 个测试文件。`test/catalog-merge.test.mjs` 有源码扫描用例，手写条目级合并会直接失败。
- **实测优先于合成**：条目已有实测 `bars` 时，`barplate` 的合成路径不再叠加。`48336` 从 4 根（2 实测 + 2 合成）回到 2 根。
- **同名异义字段分开存**：`holes` 数字（数量）与坐标数组（`holesMeasured`）并存。`catalogInterfaceConflicts()` 列出冲突，`catalog-audit` 汇总带 `interfaceConflicts` 计数（当前 5 处，全部是 `holes` 类型冲突）。
- **坐标系差异显式化**：`size` 的 x/z 互换时记 `*Frame:'rotated'` 并换轴；外形有分歧记 `'mismatch'` 时不生成连接器。**换轴方向只经 `60478` 端头把柄一个样本校核**，其余件的接口朝向仍需逐件核对。
- **重定向件**：生成器已跟随 LDraw 的 `0 ~Moved to <新编号>`，并有**真跑生成器的夹具测试**（`test/catalog-redirect.test.mjs`：搭一个只含 `60470 → 60470a` 链及相关图元的临时库，实际执行生成器，断言原编号被收录、`movedTo` 正确、`size`/`clips`/`studs` 与目标件一致、夹口确实解析出 ≥2 个）。**但生产目录尚未重建**——`catalog/parts-ldraw.json` 里仍没有 `60470`。已实测一次全量重建：新增 418 件全部是重定向件、0 删除，但 `22889`（2×6 双阶倒斜坡**开口中腔**）的分解盒被填成全宽，导致 `60239.fixed` 的 `p037/p038` 误报穿模，因此**回退未合并**。重建需先修生成器的开口中腔分解——该根因的诊断来自阅读生成器的 `decomposeHeightMap` 路径与官方 `.dat`（两个 `box3u2p` 分列 `x=±2`、中间空心），**尚未做独立的几何验证**。
- **机关几何硬检查**：`mech-axis`（转轴必须落在真实铰接上，容差 0.15 格）、`mech-range`、`mech-clearance`（行程扫掠碰撞）、`mech-rigid`（动件连通性）。
  - 运动碰撞的豁免范围已收紧并**复用真实配对规则**：豁免判定现在调用 `connectorPairMatches`（与 `partsConnected` 同一实现），要求类型真正配对（`bar↔clip` / `pin↔hole` / `pin↔axle`）、轴同向、位置容差 0.08 格 / 0.20 片，**再**检查该连接位于声明转轴上。旧实现只看「双方都属于轴类 + 距离 0.5 格内」，会把没真正扣上的零件对也放进豁免。
  - 这些是近似检查（离散采样、AABB/OBB 代理、工程容差），局限已写在 `docs/数据格式.md` §2.4 与 `src/core/core.js` 的机构检查注释里。**`mech-*` 全绿 ≠ 实物能动。**
- **回归**：`test/catalog-merge.test.mjs`（12 项）、`test/mechanism.test.mjs`（13 项）、`test/defect-gates.test.mjs`（7 项：多重集计数 + 配对规则严格性）、`test/catalog-redirect.test.mjs`（1 项真跑生成器）。

### 缺陷豁免已收紧到「错误码 + 零件集合 + 数量」

`test/known-defects.mjs` 逐条列明受影响的零件 id，`compareDefects()` 做**多重集计数**比对（不是存在性判断——否则同一条错误重复出现也能通过）：

- 多出任何一条（同类问题扩大）→ 失败；
- 少了任何一条（问题已修好但没删登记）→ 也失败，提示收紧门禁；
- **同一条重复出现**（计数翻倍）→ 失败。`test/defect-gates.test.mjs` 有专门的重复条目负例。

已用探针验证三种漂移都会被抓到：多制造一处 `mount-disconnected`、删掉一处 `mount`、把已登记的一条复制一份。

## 下一阶段：实物照片独立验收（主线）

现有全部检查都是拿同一套提取数据自证——包括本轮收紧的这些。真正的验收必须以实物照片为准：

1. **逐个确认**零件组成、接口位置、配对关系、运动方式；
2. **预期值必须来自实物观察或独立的几何核对**，不得调用当前提取器生成"标准答案"；
3. 样本明确区分三档：**照片已证明** / **仍待确认** / **当前引擎不支持**；
4. 四张照片足以启动，但未必足以确认所有型号、底孔与运动范围——不足的部分要写进"待确认"，不能默认成立。

**2026-11 更新**：机甲坐标已按把柄杆段语义重新求解，6 处扣不上的连接全部消除：

- 把柄几何修正：`48336` 的把柄从「两端支撑环两个点（±0.85）」改为官方 `4-4cylo` 的**连续杆段**（`[0, 0.4, 1, "x", 0.7]`）；`60470` 补官方 `clip3` 实测夹口（`±0.5, 0.4, 1, "+z"`）。
