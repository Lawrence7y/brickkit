## 3. A-INV-01 / P0：同一批库存 token 可以跨事务重复消费

### 3.1 真实执行反例

初始库存只有：

```text
audit-member-1：3023 ×1，黑色
audit-member-2：2412b ×1，红色
```

两次调用真实 `applyActions`，第二次明确使用第一次返回的 `_workingModel` 与 `_inventory`，没有增加任何库存：

| 时点 | 结果 |
|---|---|
| 初始 | 1 件主体 |
| 第一次 attach_assembly | passed=true，装入两件组件，模型变 3 件；结果记录消费上述两 token |
| 第一次返回库存 | 两 token 的 `state` 仍都是 `available` |
| 第二次 attach_assembly | passed=true，再次记录消费同样两 token，模型变 5 件 |
| 第二次结构校验 | 0 errors、0 warnings，库存重复消费未被检出 |

这不是单纯报告字段问题：新事务实际创建了第二套零件。

### 3.2 原因与修复范围

`apply.js` 的单件和组件路径将 token 加入当前批次的 `consumedNow`，但未更新工作库存记录的持久 state；`rehash` 又按原记录复制库存状态。

因此当前批次内的重复消费可以被拦截，下一批次清空 consumedNow 后失去消费事实。现有测试检查了 `inventoryTokens` 数量和批次内短缺，但未检查成功输出库存和第二次请求。

建议 A 修复：

- 对成功消费的每个 token 更新事务副本中的持久状态及消费来源；
- 提交时 `_inventory`、`state.inventory` 与状态哈希保持一致；
- 失败时保留当前已经通过的真回滚；
- 对 attach_part 和 attach_assembly 分别增加“成功一次 → 使用返回状态再次消费同 token → 必须拒绝”的测试；
- 保留有新库存时第二次合法装配可以通过的对照。

复现：

```powershell
node docs/prd-v2/reviews/check-A-inventory-reuse-20261026.mjs
```

当前输出 `inventoryInvariantViolated:true`。修复后该值应为 false，第二次应出现真实库存拒绝原因。证据见 [A-inventory-reuse-counterexample-20261026.json](./A-inventory-reuse-counterexample-20261026.json)。

此项修复前，不建议把 EN-03 的库存持久化标记为 verified。
