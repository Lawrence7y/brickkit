## 2. 阻断项

### B-01 / P0：R5 结构诊断与完整流程指标没有来自实际预测/搭建

位置：`tools/brickvlm/evaluate_r5.py:37`、`:51`、`:122`、`:132`。

- 数据防泄漏状态初始化为 `True`，没有执行模型族隔离检查。
- `zeroHumanInterventionCount` 和 `totalCompleted` 直接写为 3；评测器未执行三个模型的步骤、引擎动作、总装、渲染或验收。
- 结构诊断使用 `pred_err = actual_err`，并带有“达到 F1 指标”的注释。该 F1 是真值与自身比较，无法评价模型。
- 新增件“预测”从样本 `inventory` 读取，没有调用模型的 step head，也没有检查整步数量与完整清单。
- abstain、人工介入、强模型介入和失败均初始化为空/零，未从执行轨迹计算。

影响：ML-01、ML-05、ML-07、ML-08 的 VERIFIED 不成立。必须先保留旧报告并明确标为无效评测，另起 run 重新评价。

### B-02 / P0：当前实际训练与动作评测没有使用图像

位置：`tools/brickvlm/model_compact.py:51`、`train_r3_pilot.py:72`、`evaluate_r5.py:105`。

- 模型允许可选 `visual_feat`，但训练与评测均调用 `model(cand_feats)`，没有传入视觉特征。
- 没有实际读取说明书/状态图，也没有视觉编码器调用；定义一个未使用的 `visual_proj` 不等于已实现视觉理解。
- 输入仅包含候选件号的截断取模、连接器数字后缀、旋转 ID；没有目标图、实际装配图或真实几何状态。
- step head 没有对应的新增件训练损失；结构 head 的真实预测没有用于 R5 指标。

本次数据探针发现，450 个样本到模型输入的映射总共只有 **2 种特征模式**，150 个留出样本的特征全部在训练集中出现。

因此当前模块可以视为符号候选排序的 smoke 原型；不能声称已训练会理解说明书或模型结构的多模态 BrickVLM。

### B-03 / P0：数据素材和候选真值不是所声称的真实多模态验证数据

### B-06 / P0：总装审计可以放行失败任务和未知库存

位置：`src/manual-v2/workflow.js:229`。

独立反例：

1. 所有任务收据均 `status=failed`，没有消耗任何 token：返回 `ok:true`、`isConserved:false`、`errors:[]`。
2. 所有收据仍为 failed，填入 91 个不存在于任务库存的唯一 token，件号都错误：返回 `ok:true`、`isConserved:true`、`errors:[]`。

根因：任务完成只检查 taskId 是否出现；库存守恒只比较 token 集合数量，不验证精确集合、份额、件号、颜色、任务状态、版本或产物哈希。也没有实际装配状态、连接和碰撞验收。

另外，本次生成的分包是 **73 主体 + 2 保险杠 + 8 轮组 + 4 人仔 + 4 锥桶 = 91**，与报告的 `71+4+8+4+4` 不符。相关测试只检查总数，因此仍通过。

这些函数只能算收据/库存原型，不能作为四步工作流与总装完成证据。

## 4. 建议返工顺序

1. **先修评测可信性。** 推理输出与计分分离；预测路径不读取 target。完成数、介入和失败从实际轨迹计算。保留旧报告并新增无效说明，重跑使用新 run-id。
2. **重建真实数据。** 所有图像、状态、候选、哈希和审核引用实际存在且可验证；mock 与真实数据分开。建立候选位置/目标接口分布有变化的任务，避免固定选择首项即可全对。
3. **重新划分来源与结构。** 同套/同族/近重复结构不跨 split；冻结独立测试，不修改标签伪装隔离。
4. **完成真实视觉路径。** 可采用冻结视觉编码器加小型动作头的低资源方案，但需要实际图像/特征、目标状态条件与对应损失；报告视觉消融和符号基线。
5. **重做原页观察。** 正确来源、区域、步骤、翻面和总装；不存在的文件必须失败。人工标注与自动提取明确区分。
6. **修复工作流硬门禁。** 精确验证 token 集合/身份/所属任务、收据状态/版本/哈希、真实模型产物和引擎验收；接入 A 的 C1，不能用 success 布尔参数代替真实试装。
7. **正式验收在证据齐全后重跑。** 至少满足 PRD 的数据规模、独立来源、模型基线、真实会话与整体验收；资源或接口未就绪则保留 partial/unverified。
