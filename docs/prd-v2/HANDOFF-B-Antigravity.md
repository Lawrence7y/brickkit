## 1. 你拥有的工作

以 [PRD](./PRD.md) 为完整规格，重点负责 WF、MV、ML，以及 EX 的实际说明书/任务构建主线。

### B0：基线、观察、协议与资源

1. 读取现有说明书素材、`manual-pages`、`extract-plan`、diff、60239 计划与构建脚本，区分事实和推定。
2. 记录当前 plan 的来源；页码顺序均摊和默认机位不能升级为 measured。
3. 独立核准 60239 的步骤区域、跨页组件、重复、翻面、零新增件总装事件；保留原文件与区域哈希。
4. 与 A 对齐工作树快照和 C1，提交 C2 任务包、C3 数据样本、观察 Schema 和渲染需求。
5. 探测真实训练资源、基座版本、依赖与环境，给出可运行的 R0 计划。Harness 的模型名称不是本地训练基座。
6. 从开始就建立模型族级 split 和开发/测试边界，避免后期发现 60239 已被用于训练又当测试。

### B1：理解与四步流程

- 页面→区域→局部/全局步骤→组件→装配状态→动作的来源链。
- 全部零件的归总、归属和 inventory token；BOM 的盒内/使用/备件/别名/印刷身份口径分开。
- 按装配独立性拆任务；主体负责基准与挂点，子模型有局部坐标与对外接口。
- C2 任务包、状态机、试装收据、局部返工和最终总装计划。
- 先用已有可调用模型完成工作流基线，记录真实错误和成本，给后续 BrickVLM 对照。
- 新构建脚本、计划、组件产物写新路径，不改旧结果来制造成功。

### B2：视觉反馈

- 独立接口标号模块，正确遮挡、空闲/占用、局部放大与底视支持。
- 2D 标号→稳定 3D 接口映射与 stateHash，带标号理解图和无标号评分图分开。
- 说明书主图/零件框/箭头/多栏/爆炸状态分开处理；封面背景使用独立对象分割策略。
- 掩膜真值独立于掩膜算法；构建不少于 30 个多类型标注区域。
- 机位与阈值冻结，修改评分算法要提升 report version 并保留旧口径比较。

### B3：BrickVLM

- 单一视觉语言基座支持 understand_step、understand_structure、select_action、repair_local。
- 首版使用程序候选和接口检索，动作通过引擎事务执行，不能直接输出任意小数坐标。
- 数据包括合法操作、真实说明书、跨视角结构、物理合法但目标错误、局部恢复与 abstain。
- 合成数据、真实说明书与模型族划分分别记录；禁止同结构改色/换视角后跨 train/test。
- 执行 R1 基线、R2 smoke、R3 实际 SFT、R4 推理与恢复、R5 留出验收。
- 交付真实 checkpoint/adapter、精确基座、训练环境/配置/日志、数据与 split 哈希。
- 强化学习仅在监督基线与奖励反例通过后开展；本轮实际 SFT 和模型效果不能被奖励脚本替代。

### B4：实际交付与独立复核

- 使用新流程完成 60239 主体、子组件、早期试装、总装和全部步骤回放，生成新的 viewer/PDF/MPD 候选。
- 关键总装/导出问题提交 A，由 A 修核心与公共入口，避免维护第二份几何算法。
- 在冻结候选上独立复跑 A 的 fake-group、环、父件穿模、24 姿态、嵌套重算和输出兼容测试。
- 接受 A 对你的数据、模型身份、权重加载、训练与评测过程的独立复核，完整保留失败与介入。

## 4. 训练与效果状态必须区分

| 状态 | 可以声称什么 |
|---|---|
| 有设计与 Schema | 领域任务已定义 |
| 数据生成通过 | 已有可验证样本 |
| smoke 通过 | 训练链路可运行 |
| 已保存且可加载 adapter | 实际完成了相应训练运行 |
| validation 有改善 | 开发评估改善，仍待留出验证 |
| 独立测试与完整流程达标 | 可声称对应范围的小模型已验证 |

不得以“训练命令已启动”“loss 下降”“输出合法 JSON”“被引擎拒绝后没有坏模型产物”代替动作正确与整书完成。

如果资源不足，不隐藏事实、不无限等待；完成可做的数据、协议、基线和推理适配，给出具体缺口和可复现后续命令，保持 R3/R5 未完成。
