# brickbuild 数据格式 0.2

一个模型由两个 JSON 文件描述：

| 文件 | `format` | 作用 | Schema |
|---|---|---|---|
| `xxx.brick.json` | `brickbuild` | 零件、位置、步骤、模块、可开合设计 | `schema/brickbuild.schema.json` |
| `xxx.photos.json` | `brickbuild-photos` | 用户拍的照片清单（拍摄规范见 `拍摄规范.md`） | `schema/photoset.schema.json` |

零件编号和颜色都用 **LDraw 标准**（`catalog/parts.json`、`catalog/colors.json`），所以可以无损导出到 Studio / LeoCAD / LPub3D。

---

## 1. 单位与坐标

| 量 | 单位 | 实际尺寸 | LDraw |
|---|---|---|---|
| x、z | 格（1 个凸点间距） | 8 mm | 20 LDU |
| y | 片（1 块薄板的高度） | 3.2 mm | 8 LDU |

- 一块标准砖高 3 片，薄板 / 平板高 1 片。
- **y 向上**，第 0 层是地面（底板最底面）。
- **正面 = +z**（`meta.front` 固定为 `"+z"`），站在正面看模型时右手边是 **+x**。
- `at = [x, 层, z]`：零件**旋转后**占地范围的最小角（x 最小、z 最小的那一格），以及零件底面所在的层。必须是整数。
- `rot`：绕竖直轴旋转，**俯视逆时针**，只能是 `0 / 90 / 180 / 270`。
- 目录里的 `size = [本地 x 格数, 本地 z 格数]`；`rot` 为 90 / 270 时两者互换。
- 斜面砖 `rot: 0` 时凸点在后排（−z），坡面朝向正面（+z）。
- 门与门框使用相同的 `at / rot`；门本身不占格子（目录里 `occupies: false`），用 `mount` 指向门框。

示例：一块红色 2×4 砖放在原点

```json
{ "id": "p001", "part": "3001", "color": 4, "at": [0, 0, 0], "rot": 0, "step": 1 }
```

占据 x 0–3、z 0–1、第 0–2 层；它的凸点在第 3 层，上面的零件 `at[1] = 3` 才能扣上。

## 2. 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `format` | ✔ | 固定 `"brickbuild"` |
| `version` | ✔ | `"0.2"` |
| `meta` | | `name`、`author`、`createdAt`、`front`（`"+z"`）、`description`、`photoSet`（照片清单文件名） |
| `parts` | ✔ | 零件数组 |
| `steps` | | 步骤标题与说明；不写时按 `parts[].step` 自动生成 |
| `modules` | | 模块（爆炸图“按模块”、图纸子组件） |
| `mechanisms` | | 可开合设计（门、盖子、抽屉、可取下的屋顶…） |

### 2.1 `parts[]`

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | 唯一 id，例如 `p001` |
| `part` | ✔ | LDraw 零件编号，例如 `3001`（砖 2×4） |
| `color` | ✔ | LDraw 颜色代码，例如 `4` 红、`15` 白、`71` 浅蓝灰 |
| `at` | ✔ | `[x 格, 层(片), z 格]`，见上文 |
| `rot` | | `0 / 90 / 180 / 270`，默认 0 |
| `up` | | 凸点朝向：`"+y"`（默认朝上）/ `"-y"`（倒装）/ `"+z" / "-z" / "+x" / "-x"`（SNOT 四面侧装） |
| `snot` | | 沿 `up` 方向叠放的片数偏移（整数，默认 0） |
| `step` | ✔ | 第几步放上（≥1 的整数） |
| `module` | | 所属模块 id（0.1 的 `group` 仍兼容） |
| `mount` | | 不靠凸点连接时，安装在哪个零件上（门 → 门框） |
| `status` | | `confirmed` 照片里看得到 / `inferred` 推断（被遮挡）/ `uncertain` 存疑，需要人工确认 |
| `confidence` | | 0–1，识别置信度 |
| `evidence` | | 能看到这个零件的照片 id 列表 |
| `note` | | 备注 |

### 2.2 `steps[]`

```json
{ "n": 15, "title": "装上屋顶", "note": "对准四个角放下", "attach": "roof" }
```

- `n`：步骤号，对应 `parts[].step`。
- `attach`：**装配步**，把一个子组件（`modules[].subassembly = true`）整体装到主体上。这一步可以没有零件；子组件里所有零件的 `step` 都必须早于装配步。

### 2.3 `modules[]`

```json
{ "id": "walls", "label": "墙体", "explode": [0, 16, 0] },
{ "id": "door",  "label": "前门", "parent": "walls", "explode": [0, 0, 6] },
{ "id": "roof",  "label": "屋顶", "subassembly": true, "explode": [0, 34, 0] }
```

| 字段 | 说明 |
|---|---|
| `id` / `label` | 模块 id 与显示名称 |
| `parent` | 父模块；爆炸位移会**叠加**父级（上例中门 = 墙体位移 + 自己的位移） |
| `explode` | “按模块”爆炸到 100% 时的位移 `[x 格, 层(片), z 格]`；不写则自动按高度排开 |
| `subassembly` | 单独拼好再整体装上的**子组件**。图纸里它的步骤会放进“子组件”框，并在装配步画出装配箭头；LDraw 导出为 MPD 子文件 |
| `note` | 备注 |

**爆炸图两种模式**

- **按层级**：按零件底面高度分层，每一层向上拉开，适合看内部结构。不需要任何额外数据。
- **按模块**：每个模块按 `explode` 整体移开，适合看“这个模型由哪几部分组成”。

### 2.4 `mechanisms[]`

| `type` | 必填字段 | 含义 |
|---|---|---|
| `hinge` 合页 | `pivot`、`axis`、`range` | 绕转轴旋转；`pivot` 为转轴上一点 `[x 格, 层(片), z 格]`，`axis` 为方向，`range` 为角度（度），例如 `[0, 95]` |
| `slide` 滑动 | `axis`、`range` | 沿 `axis` 平移；`range` 为距离（每单位 = 1 格或 1 片） |
| `removable` 可取下 | `offset` | 取下时的位移 `[x 格, 层(片), z 格]` |

共有字段：`id`、`label`、`parts`（参与运动的零件 id）、`default`（初始状态）、`evidence`（打开状态的照片 id）。

## 3. 校验代码

`brickkit validate` 输出 `errors`（必须修）、`warnings`（建议修）、`info`（提示）。每条都有 `code`、`msg`、`parts`（相关零件 id，查看器里会高亮）。

| 代码 | 级别 | 含义 |
|---|---|---|
| `model` / `parts` / `part` | 错误 | 文件不是对象 / `parts` 不是数组 / 某个零件不是对象 |
| `id` / `id-dup` | 错误 | 零件缺少 id / id 重复 |
| `part-unknown` | 错误 | 目录里没有这个零件编号 |
| `at` / `rot` / `step` | 错误 | 坐标不是 3 个整数 / 旋转不合法 / 步骤号不合法 |
| `overlap` | 错误 | 两个零件占了同一个格子 |
| `floating` | 错误 | 零件没有通过凸点或 `mount` 连到底座（悬空） |
| `mount` | 错误 | `mount` 指向不存在的零件 |
| `modules` / `module-id` | 错误 | `modules` 不是数组 / 模块 id 缺失或重复 |
| `module-parent` / `module-cycle` | 错误 | `parent` 指向不存在的模块 / 形成循环 |
| `module-explode` | 错误 | `explode` 不是 3 个数字 |
| `sub-attach` | 错误 | 子组件没有对应的 `attach` 装配步 |
| `attach` | 错误 | `attach` 指向不存在的模块或不是子组件 |
| `attach-order` | 错误 | 子组件的零件步骤不早于装配步 |
| `mech-id` / `mech-type` / `mech-parts` | 错误 | 可开合设计 id、类型或零件不合法 |
| `mech-hinge` / `mech-slide` / `mech-removable` | 错误 | 缺少该类型的必填字段 |
| `format` | 警告 | `format` 不是 `brickbuild` |
| `color-unknown` | 警告 | 颜色代码不在颜色表中 |
| `status` | 警告 | `status` 取值不合法 |
| `step-undefined` | 警告 | 零件的步骤没有在 `steps` 中定义 |
| `step-order` | 警告 | 某一步放的零件在这一步还没有支撑（支撑它的零件在后面的步骤）；子组件在装上之前只需连到它自己的最底层 |
| `module-unknown` | 警告 | 零件的 `module` 没有在 `modules` 中定义 |
| `sub-empty` / `sub-mixed` | 警告 | 子组件没有零件 / 同一步混了子组件和主体的零件 |
| `door-mount` | 警告 | 门没有用 `mount` 指明门框 |
| `ground` | 警告 | 最低零件不在第 0 层 |
| `mech-evidence` | 警告 | 可开合设计没有关联打开状态的照片 |
| `evidence` | 警告 | （`--photos` 时）证据照片在照片清单里找不到 |
| `inferred` / `uncertain` | 提示 | 推断 / 存疑零件的数量与列表，需要用户确认 |

`check-photos` 的警告代码：`mech-half`（合页 / 滑动建议补半开）、`photo-id`、`photo-dup`、`resolution`（长边 < 3000px）、`detail`（没有特写）、`reference`（没写尺寸参照）。缺少的机位放在 `missing` 里。

## 4. 导出 LDraw / MPD

`brickkit export-ldraw model.brick.json -o out.mpd`

| brickbuild | LDraw |
|---|---|
| 1 格 / 1 片 | 20 LDU / 8 LDU |
| y 向上、正面 +z | y 向下、正面 −z（绕 X 轴转 180°） |
| `part` / `color` | `xxxx.dat` / 颜色代码原样 |
| 每一步 | `0 STEP` |
| 步骤标题 | `0 // 第 n 步：标题` |
| 子组件 | MPD：`0 FILE main.ldr` + 每个子组件一个 `0 FILE roof.ldr`，主模型在装配步插入 `1 16 0 0 0 1 0 0 0 1 0 0 0 1 roof.ldr` |
| 可开合设计 | 注释行 `0 // 可开合：…`（LDraw 没有对应语义） |

没有子组件时导出单个 `.ldr`。子组件在 MPD 里与主模型使用同一坐标系，LPub3D 可以直接按子组件生成说明书。

## 5. 版本变化

**0.2**（当前）
- 新增 `modules[]`（`parent`、`explode`、`subassembly`），`parts[].module` 取代 `group`（旧字段仍兼容）。
- 新增 `steps[].attach` 装配步。
- 查看器：爆炸图“按层级 / 按模块”、拼装图纸（说明书）模式。
- LDraw 导出：有子组件时输出 MPD。

## 6. 辅助数据文件

### 6.1 `xxx.observations.json`（`brickbuild-observations` 0.1）

把「照片里看到什么」固化为可对账数据（视觉模型逐张观察 + 拍摄备注合成），供 `brickkit check-observations` 与模型 BOM 数值对账。示例见 `examples/lantern.observations.json`。

| 字段 | 说明 |
|---|---|
| `format` / `version` | 固定 `"brickbuild-observations"` / `"0.1"` |
| `photos[].id` / `photos[].observed` | 照片 id（须与 photos.json 一致）/ 该照片看到的现象（自由文本数组） |
| `inventory[].feature` | 特征名（如「四角柱」） |
| `inventory[].part` | 候选零件编号数组（候选 ≠ 确认） |
| `inventory[].color` | LDraw 颜色代码，单值或数组 |
| `inventory[].count` | 数量区间 `[min, max]`（含端点） |
| `inventory[].evidence` | 支持该条目的照片 id 数组 |
| `dimensions` | 比例约束说明（从照片程序化实测后回填） |

`check-observations` 判定：候选零件×颜色集合在模型 BOM 中的总量落在区间 → 通过；区间外 `warning obs-count`；总量 0 → `error obs-missing`；模型 BOM 中不被任何 inventory 覆盖的 `(part, color)` → `warning model-extra`；`evidence` 引用不存在的照片 → `warning obs-evidence`。

### 6.2 diff 对账报告（`outDir/report.json`）

| 字段 | 说明 |
|---|---|
| `mode` | `joint`（默认，联合标定）/ `sweep`（旧逐照片择优）/ `fixed`（仅清单姿态 + 4 向滚转，批量变体筛选） |
| `yawDelta` | joint 模式解出的全组共享 yaw 偏移（度） |
| `photos[].silhouetteIoU` / `silhouetteIoURaw` | 尺度归一后 / 未归一的轮廓 IoU（后者作比例惩罚） |
| `photos[].scale` / `bboxAspectSim` / `colorSim` / `structureSim` | 面积比缩放因子 / 长宽比相似度 / 颜色直方图余弦 / 色块结构相似度（16×16 网格众数粗色类一致率） |
| `photos[].bestAz` / `bestRoll` / `poseAz` / `poseEl` / `roll` | 诊断用姿态（最优方位角 / 滚转 / 打分方位角 / 打分俯仰角；manual 的 `poseEl` 来自 elevation 扫描） |
| `photos[].kind` / `source` | 清单条目的 kind；`source: "manual"` 标注说明书页来源（白底渲染图，非实拍） |
| `photos[].maskConfidence` / `degraded` | 照片掩膜边界吸收率 / 是否退化为椭圆保底（manual 条目掩膜不标 degraded） |
| `overall.meanIoU / meanColorSim / meanStructureSim / score` | 加权均值（degraded 照片降权 0.3，`degradedPhotos` 列出） |

总分口径：joint / fixed = `0.35*iou + 0.15*aspect + 0.20*color + 0.20*structure + 0.10*rawIoU`；sweep 沿用旧公式 `0.5/0.2/0.3`。CLI 以 `overall.score ≥ 0.6` 为达标门槛（退出码 0 / 1）。

### 6.3 说明书页条目（`kind: "manual"`）

照片清单里除实拍照片外，可以混入**说明书页**——官方/自渲染的白底 3D 视图（任意 3/4 视角，`azimuth`/`elevation` 按页面机位标注，`elevation` 只作候选之一）。`brickkit diff` 对它走一等通道（实现见 `src/core/diff.js`）：

| 方面 | manual 条目行为 |
|---|---|
| 掩膜 | **近白像素即背景**：Lab 明度 L ≥ 95 且 \|a\|、\|b\| ≤ 4，从四条边洪泛近白连通区取反为前景；模型内部孤立的白色零件不与边界连通，保留为前景。四条边近白占比 < 0.95（页面其实不是白底）时退回实拍容差扫描取最优，但仍**跳过椭圆窗保底**——它是为实拍杂乱背景设计的，对页图是噪声 |
| degraded 降权 | manual 掩膜永不标 `degraded: true`，总分均值不降权、yaw 投票不降权 |
| 姿态扫描 | 在原有 yaw 择优（joint 粗扫标注 ±30°）基础上**叠加 elevation 扫描**：默认 5°..40° 步 5°（`diff.js` 常量 `MANUAL_EL_FROM/TO/STEP`，代码调用 `runDiff` 时可用 `opts.manualEls` 覆盖；CLI 暂不暴露该参数）。joint 模式正式打分冻结粗扫选出的 `(roll, el)` |
| 报告 | 条目带 `kind: "manual"` 与 `source: "manual"`，便于在 `report.json` 里区分实拍与页图来源 |

典型用法：把 `brickkit render --az 35 --el 26` 生成的白底渲染图作为一条 `manual` 条目放入 photos.json，即可用同一套 diff 对账「模型 ↔ 说明书页」的视角一致性（自渲染对自渲染应接近满分，可当回归自检）。

### 6.4 `xxx.plan.json`（`brickbuild-plan` 0.1，说明书蓝图 + 零件守恒门禁）

把说明书的**步骤树 / 子模型拆分 / 每步视角初值 / 零件预算**固化成可机检的蓝图，在做任何搭建之前先过零件守恒门禁（`brickkit check-plan`）。由 `brickkit extract-plan`（`tools/extract-plan.mjs`）生成，也可手写后再校验。示例见 `examples/60239.plan.json`。

```bash
# 从模型反推每步新增零件，并用说明书页分类补页码（无模型时只能 --from-pages 单独出页骨架）
node cli/brickkit.mjs extract-plan --from-model examples/60239.brick.json \
  --from-pages out/manual-pages/60239/manifest.json --bom examples/60239.bom.json \
  -o examples/60239.plan.json
# 门禁：全量对账（plan 内部守恒 + 官方 BOM + 模型实际）
node cli/brickkit.mjs check-plan examples/60239.plan.json \
  --bom examples/60239.bom.json --model examples/60239.brick.json
```

最小示例：

```json
{
  "format": "brickbuild-plan",
  "version": "0.1",
  "meta": { "name": "LEGO 60239 警察巡逻车", "setId": "60239" },
  "bomFile": "examples/60239.bom.json",
  "manual": { "pdf": "assets/instructions-lego/60239_book1.pdf",
              "pagesDir": "out/manual-pages/60239", "pages": 36 },
  "submodels": [
    { "id": "main", "label": "主干", "steps": [1, 15], "attachStep": null,
      "bom": [{ "part": "28324", "color": 15, "qty": 1 }] }
  ],
  "steps": [
    { "n": 1, "page": 2, "pageConfidence": "assumed", "az": 300, "el": 20,
      "parts": [{ "part": "28324", "color": 15, "qty": 1 }] }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `format` / `version` | ✔ | 固定 `"brickbuild-plan"` / `"0.1"`，其余值直接 error |
| `meta.name` / `meta.setId` | | 模型名 / 套内编号（`extract-plan` 从 `bom.set` 去掉 `-1` 后缀、或文件名里的 4–6 位数字取） |
| `meta.generatedBy` / `generatedAt` / `source` | | 生成工具 / 时间 / 来源 `.brick.json`（手写时可省） |
| `bomFile` | | 关联的官方 BOM（`brickkit-bom`）路径 |
| `manual.pdf` / `manual.pagesDir` / `manual.pages` / `manual.book` | | 说明书 PDF 路径 / 逐页 PNG 目录 / 总页数 / 分册号 |
| `submodels[]` | ✔ | 子模型（`main` 恒为第一个，可与其它区间重叠） |
| `submodels[].id` / `label` | ✔ / | 子模型 id / 显示名 |
| `submodels[].steps` | | `[起始步骤, 结束步骤]`（含端点）；由成员步骤的 min..max 推出，或 `--assign` 显式声明；无法确定时为 `null` |
| `submodels[].stepList` | | 该子模型实际出现的步骤号列表（`extract-plan` 写出，只读诊断字段） |
| `submodels[].attachStep` | | 总装到主体的步骤号；`null` = 主干或未声明（来源：`steps[].attach` 或 `mounts[]`） |
| `submodels[].bom[]` | ✔ | 该子模型的零件预算 `[{part, color, qty}]`（全部子模型之和必须等于全部步骤之和） |
| `submodels[].source` / `note` | | 归属证据（`assign` / `modules` / `submodels` / `fallback`）/ 说明 |
| `steps[]` | ✔ | 步骤数组（按 `n` 升序） |
| `steps[].n` | ✔ | 步骤号（整数，不可重复） |
| `steps[].page` | | 说明书页码（整数）或 `null`（无可用页） |
| `steps[].pageConfidence` | | `measured`（有显式 page/step 对应声明）或 `assumed`（顺序均摊）；**assumed 必带 `note` 说明来源** |
| `steps[].pageKind` | | 该页在 manifest 里的分类（`cover` / `step` / `parts-list` / `other`） |
| `steps[].az` / `el` | | 该步说明书视图的方位角 / 俯仰角初值 |
| `steps[].poseConfidence` | | `measured`（`--poses` 提供或已 calibrate 回填）/ `assumed`（默认初值 `az=315, el=25`） |
| `steps[].parts[]` | ✔ | 本步新增零件 `[{part, color, qty}]` |
| `steps[].note` | | 页码/视角来源说明（共用页、均摊等） |
| `pageMapping` | | 页码口径审计：`source`（manifest 路径）、`method`（`declared` / `even-split` / `mixed` / `none`）、`stepPages`、`stepCount`、`measuredSteps`、`assumedSteps` |
| `assumptions[]` / `notes[]` | | 提取器显式登记的口径假设 / 注意事项（不静默猜） |

`extract-plan` 参数：`--from-model`（必需，从 `parts[].step` 反推每步零件）、`--from-pages`（manifest，补 `page`/`pageKind`）、`--bom`（写 `bomFile` 并报件数差）、`--assign`（子模型归属：扁平映射 `{partId: submodelId}`，或 `{submodels:[{id,label,steps,attachStep,parts}], assign:{partId:submodelId}}`）、`--poses`（`{steps:{"1":{az,el}}, pages:{"8":{az,el}}}`，标 `poseConfidence=measured`）、`--page-map`（`{"步骤号": 页码}`，标 `pageConfidence=measured`）、`-o`（默认 `<model>.plan.json`）。

子模型归属优先级：① 模型 `modules[].subassembly`（沿 `parent` 链找最近的子组件）→ ② 模型 `submodels` / `parts[].submodel` → ③ `--assign` 显式映射 → ④ 全部归 `main`。模型自带归属时 `--assign` 被忽略并在 `notes` 里说明；要强制覆盖，在 `--assign` 文件里写 `"override": true`。

#### 校验规则与错误码（`brickkit check-plan` 退出码 0 = ok / 1 = 有 error）

| 代码 | 级别 | 触发条件 |
|---|---|---|
| `plan-format` / `plan-version` | error | `format` 不是 `brickbuild-plan` / `version` 不是 `0.1` |
| `plan-structure` | error | 结构不合法：`steps`/`submodels` 非数组、`n` 非整数、`steps` 区间非「整数[起,止]且升序」、`attachStep` 非整数、`parts[].qty` 非正整数、缺 `part`/`color` |
| `plan-dup` | error | 步骤号或子模型 id 重复 |
| `plan-step-sum-mismatch` | error | `∑steps[].parts.qty ≠ ∑submodels[].bom.qty`：报差值 `delta` 与逐 (件号,颜色) 明细（`detail[].diff`，前 12 条） |
| `plan-bom-missing` / `plan-bom-extra` | error | 给了 `--bom` 时逐 (件号,颜色) 对账：plan 少于 / 多于官方 BOM（报 `need` / `excess` 与两侧数量）。替代件（`substituteFor`）无论 plan 写替代件号还是官方 `design` 件号都放行 |
| `plan-substituted` | warning | 放行的替代件明细（`design` / `substitute` / `color` / `qty`） |
| `plan-bom-file` | error | `--bom` 文件不是 `brickkit-bom`（缺 `parts` 数组） |
| `plan-step-overlap` | error | 两个非 `main` 子模型的步骤区间重叠（`main` 与其它重叠属正常，例外） |
| `plan-attach-order` | error | `attachStep` 早于该子模型自身区间末（应先拼完再装） |
| `plan-model-drift` | error | 给了 `--model` 时，模型实际 BOM 与 `submodels[].bom` 汇总不符（缺件/多件逐类列出） |
| `plan-unknown-field` | warning | 出现白名单外的字段（拼写错误不再被静默丢弃）：报 `where` 与 `field` |
| `plan-confidence` | warning | `pageConfidence` 不是 `measured` / `assumed` |

`stats` 输出：`steps` / `submodels` / `planTotalParts`（= `stepsTotalParts`）/ `submodelsTotalParts` / `bomEntries` / `bomTotalParts` / `modelTotalParts` / `substituted`。

**诚实口径**：`extract-plan` 只写数据里能直接推出的事实。页码只能按顺序均摊时全部标 `pageConfidence: "assumed"` 并在 `note` 与 `assumptions[]` 里写明「按顺序均摊、未经 OCR/文字层核对」；没有 `--poses` 时视角一律 `poseConfidence: "assumed"`。若要精确页码/视角，用 `--page-map` / `--poses` 显式声明（标 `measured`）或先用 `brickkit calibrate` 标定后回填。
